# Acceptance / manual test checklist

## ระบบหลัก
- เปิดหน้าเมนูบนมือถือและ desktop, category/sort/page, basket quantity, loading/empty/error
- สร้าง order แล้วตรวจราคา snapshot กับ shared-PK queue และ token
- เมนู CRUD, order CRUD ผ่าน Swagger/API โดย staff login + CSRF
- ลูกค้าใช้ token คิวอื่นไม่ได้; anonymous ไม่ดู staff list/advance/write menu
- แก้ WAITING ได้, PREPARING แก้ไม่ได้, cancel WAITING/PREPARING, READY cancel409
- ออเดอร์ที่มี log และเมนูที่มีประวัติลบไม่ได้

## Real Push บน Render HTTPS
1. ตั้ง STAFF_PASSWORD และกุญแจเดิมใน Render ไม่เปิดเผย secrets
2. อัปเดตโค้ดผ่าน PR/push ของสมาชิกเอง แล้วรอ Live และ health UP
3. มือถือ A สั่งและเปิด Push; มือถือ B สั่งและเปิด Push คนละออเดอร์
4. ล็อกจอ A ก่อน แล้วพนักงานอีกเครื่องเลื่อนเฉพาะ A เป็น READY
5. ตรวจ A แจ้งเตือนเลขคิวถูกต้อง และ B ไม่ได้รับ
6. แตะแจ้งเตือนแล้วเข้าหน้าคิวบนเครื่องเดิมได้; ไม่มี token ใน URL
7. ตรวจ log ACCEPTED กับการแสดงบนโทรศัพท์แยกกัน
8. B ไม่อนุญาต Push ยังติดตามผ่านเว็บได้
9. restart app แล้ว order/subscription/token hash ใน DB อยู่; staff login ใหม่ได้

ผลที่มีจากรุ่น demo เดิม: Android รับ Push หลังการกดส่งแล้วกลับโฮม/ล็อกจอ. ยังไม่ใช่หลักฐานว่ารุ่น order READY ใหม่ผ่าน real device test. เก็บ screenshot/date/device/commit ใหม่ใน img/.

## Release
- clean verify ผ่านบน commit ที่ส่งจริง
- diagrams/solid line references/README/Test Report ตรงโค้ด
- main ผ่าน PR มี reviewer; URL + Swagger เปิดวันนำเสนอ
- อธิบาย State/Observer/Strategy และ price/token/transaction ได้ทุกคน

## ผลตรวจ localhost วันที่ 8 ตุลาคม 2026

ผ่าน: สั่งอาหารจาก basket, แก้จำนวนและยอดรวม, เข้าสู่ระบบพนักงานจริง, เปลี่ยนสถานะ PREPARING/READY/COMPLETED, หน้าลูกค้าแสดง READY และจำกัดการแก้ไข, บันทึกฟอร์มเมนู, สร้าง QR ตัวอย่าง.
ยังรอ: QR ของ URL จริง, responsive บนมือถือจริง, สองออเดอร์บนสองเครื่อง และ READY Push ขณะล็อกจอจาก Render รุ่นใหม่.

## ผลตรวจ Android จากทีม วันที่ 8 ตุลาคม 2026

กานดิทัตยืนยันว่าอนันต์เอกก์ได้รับแจ้งเตือนบน Android จริงแม้ล็อกจอ. ยังต้องเก็บหลักฐานพร้อม URL ที่ใช้ และตรวจสองเครื่อง/สองออเดอร์เพื่อยืนยันว่าแจ้งเตือนถึงเจ้าของคิวเท่านั้น. ผลนี้ไม่แทนการทดสอบ Render รุ่นส่งมอบ.

## ภาพเมนูและปุ่มลบ

- [ ] เพิ่มเมนูพร้อมภาพ JPG/PNG: เห็นตัวอย่างก่อนบันทึก และเห็นภาพเดียวกันในหน้าลูกค้า
- [ ] แก้ไขเมนูเปลี่ยนภาพ: ภาพใหม่แสดงหลังบันทึก/refresh; ไม่เลือกไฟล์ใหม่ต้องคงภาพเดิม
- [ ] เปลี่ยนชื่อเมนูแล้วภาพที่อัปโหลดยังคงอยู่; restart แอปแล้วอ่านภาพได้
- [ ] ไฟล์เสียหาย/ชนิดอื่น/เกิน 2 MB ต้องแสดงข้อผิดพลาดและไม่สร้างเมนูค้าง
- [ ] การ์ดเมนูมีเฉพาะแก้ไข; ปุ่มลบมีเฉพาะฟอร์มแก้ไข ไม่แสดงตอนเพิ่ม และถามยืนยัน
- [ ] เมนูมีประวัติออเดอร์ลบไม่ได้และแนะนำให้ปิดขาย
