# Acceptance checklist

รายการนี้เป็นเงื่อนไขตรวจหลังรวมงานครบ ไม่ใช่ผลผ่านครบระบบ

- [ ] ลูกค้าเลือกเมนู/จำนวน สั่งจริง และได้เลขคิวพร้อมวันที่
- [ ] ประวัติและติดตามคิวใช้ token ของแต่ละบิล ไม่เปิดข้อมูลข้ามออเดอร์
- [ ] แก้ไขเฉพาะ WAITING และยกเลิกตามกฎ State; คำขอซ้ำไม่เกิดผลซ้ำ
- [ ] พนักงานล็อกอิน/ล็อกเอาต์ได้ และทุก API ที่จำกัดสิทธิ์ตรวจสิทธิ์/CSRF จริง
- [ ] เมนู JSON/multipart, รูปภาพ, ปิดขาย และป้องกันลบเมนูที่มีประวัติทำงานร่วมกับ UI
- [ ] เลขคิว Bangkok ข้ามวันเริ่มใหม่ การสั่งพร้อมกันไม่ซ้ำ และ rollback ไม่กินเลข
- [ ] พนักงานเปลี่ยนสถานะตามลำดับที่อนุญาตและลูกค้าเห็นผล
- [ ] สมัคร/ยกเลิก Subscription และรับ Push เมื่อ READY บนอุปกรณ์จริงผ่าน HTTPS
- [ ] การแจ้งเตือนซ้ำ/ส่งล้มเหลว/Subscription หมดอายุมีผลและ Log ตามข้อกำหนด
- [ ] QR สแกนเปิดหน้าเมนูบนโทรศัพท์ได้ และพิมพ์หลังภาพพร้อม
- [ ] รัน JS และ Maven ครบผ่าน เก็บผล browser จริงและภาพหลักฐานรอบล่าสุด
- [ ] ทดสอบ Docker startup, health และ migration กับฐานที่สำรองแล้ว

K/A module tests มีหลักฐานบางส่วนแล้ว ดู test-report; งาน C/T และ full browser acceptance ยังรอรวมงาน
