# SOLID analysis

เอกสารนี้อ้างอิงโค้ดที่รวมใน `develop` baseline `87070b5` หลัง PR #79 เมื่อ 10 ตุลาคม 2026 ลิงก์โค้ดระบุบรรทัดของ baseline นี้เพื่อให้ตรวจหลักฐานได้ ผล Java full suite ล่าสุดที่ทีมส่งคือ 285 tests ผ่านทั้งหมดใน C-R17; การแก้เอกสารชุดนี้ไม่ได้รัน tests ใหม่และไม่ถือเป็นการรับรองว่าทุกคลาสไม่มีข้อบกพร่อง

## ตัวอย่างการไหลของ dependency

QueueController รับ QueueService; runtime ใช้ QueueServiceImpl ซึ่งรับ OrderAccessService, QueueMapper, List<QueueStateHandler>, ApplicationEventPublisher และ Clock จาก constructor รายละเอียดสิทธิ์และ lock อยู่ใน OrderAccessServiceImpl รายละเอียด transition อยู่ใน State handler และผลลัพธ์ API อยู่ใน QueueMapper

ReadyNotificationObserver รับ NotificationDeliveryService และเรียกหลัง commit ส่วน delivery service รับ NotificationStrategy ผ่าน ObjectProvider เมื่อเลือก PushNotificationStrategy จะเรียก WebPushSender ซึ่ง runtime ใช้ BrowserWebPushSender ตัว sender รับ PushConfigurationService สำหรับ public key โดยยังตรวจ private/public key pair และ subject ก่อนส่ง

การสร้าง DTO, entity, QueueContext ต่อ operation และ object ของ Web Push library ภายใน adapter ไม่ใช่การสร้าง business service implementation เพื่อข้าม interface การพึ่ง SDK ภายนอกถูกจำกัดไว้ที่ BrowserWebPushSender; ข้อ DIP ที่แก้ใน T-R18 คือการสร้าง **PushConfigurationServiceImpl** ใน sender โดยตรง

## ขอบเขตและข้อจำกัดที่ต้องอธิบายได้

- OCP ไม่ได้หมายความว่าเพิ่มสถานะหรือช่องทางใหม่แล้วไม่แก้ไฟล์ใดเลย สถานะใหม่ต้องปรับ QueueStatus/handler registry ให้ครอบคลุมทั้งหมด ส่วนช่องทางใหม่อาจต้องปรับ configuration, การสร้าง claim และ log metadata เพราะ delivery service ปัจจุบันยังรู้จัก console/webpush
- Console และ Web Push มีผลต่างกันตาม contract: console คืน 0 และไม่ได้ส่ง provider ส่วน webpush อาจคืน error status หรือโยนข้อผิดพลาด ผู้เรียกต้องไม่ตีความทั้งสองแบบว่าแสดงแจ้งเตือนแล้ว
- State handlers เป็น stateless beans; QueueContext สร้างใหม่ต่อ operation เพื่อเก็บ queue/state snapshot และต้องอยู่ใน synchronized writable transaction ไม่ควรนำ context เดิมไป advance ซ้ำหลังเปลี่ยนสถานะ
- Tests ที่ใช้ mock/fixture ตรวจสัญญาเฉพาะส่วน ส่วน QueueStateIntegrationTest และ ReadyNotificationIntegrationTest ตรวจ transaction/persistence จริงกับฐานทดสอบ โดยยังไม่ยืนยันพฤติกรรม provider หรือ popup บนอุปกรณ์จริง
- ตารางนี้แสดงหลักฐานและขอบเขตของ S/O/L/I/D ไม่ใช้ชื่อ annotation หรือ interface เพียงอย่างเดียวเป็นข้อสรุปว่าทุกคลาสผ่าน SOLID
